## Handoff — specialist completes

- Result and acceptance criteria met/unmet: **Met for the read-only audit.** The present overlap has one direct cause: `capital-location-choice-label` is a single MapLibre symbol layer with hard-coded anchors/offsets by `capitalLocationChoiceIndex` and both `text-allow-overlap` and `text-ignore-placement` set to `true` (`src/maplibre/maplibre-activity-runner.js`, lines 4444–4474). Every capital is index 0 and every pair of distractors is index 1/2, so dense same-state points always use the same three layouts, regardless of zoom, viewport edge, label length, nearby star, or one another. MapLibre cannot solve this while all labels are forced to render. The existing question state correctly limits disclosure to feedback: the three target-state choices, plus a selected wrong-state city when applicable; pre-answer labels/stars remain off. That contract should remain the sole gate for any new layout.

  Recommended reusable screen-space design: add one small, renderer-owned `CapitalLocationFeedbackLabelOverlay` module under `src/maplibre/` and have `MapLibreActivityRunner` own its lifecycle. Render labels as measured, absolutely positioned, `aria-hidden`, `pointer-events: none` HTML elements and leader lines as a sibling, `aria-hidden` SVG in the map container. Keep the MapLibre capital-choice marker, hit, and feedback-star layers unchanged; hide/retire only `capital-location-choice-label` when the overlay is active. This is preferable to `text-variable-anchor`: MapLibre collision can choose an anchor or omit a label, but it does not expose the final boxes for reliable leader lines and cannot guarantee all three/four feedback labels remain visible.

  The module should accept only the revealed choices, map projection, viewport/protected rectangles, and font metrics; it must not receive state/city-specific offsets. After creating hidden label elements, measure their actual boxes with `getBoundingClientRect()`. Project each source longitude/latitude to map-local pixels and build protected rectangles for every revealed dot, with an enlarged capital-star exclusion (star bounds plus 6 px). Also reserve a small inset at map edges and the current MapLibre control rectangles. Place labels deterministically in this order: capital first; then the selected wrong-state city, if any; then target-state distractors in `choiceIndex` order. For each label, try generic compass positions (NE, NW, SE, SW, E, W, N, S) on successively wider rings; center each candidate against its measured box, reject any candidate outside the safe viewport, intersecting a protected marker/star rectangle, an already accepted label box (include a 4 px gutter), or an accepted leader segment. Score remaining valid candidates by nearest-ring, then lowest displacement, then stable candidate order. If the normal rings are exhausted, use deterministic, non-overlapping edge callout lanes (top/bottom/left/right inside the safe viewport) before admitting any overlap; the feedback contract requires showing all disclosed labels. Store the chosen box, source point, and whether the placement exceeds a 32 px source-to-box-edge threshold.

  Draw a leader only for that latter, materially displaced case. Its line starts at the edge of the source marker/star exclusion and ends on the nearest edge of the label box; use a 1–1.25 px, muted ink line with a white under-stroke, no arrowhead, and no hit testing. Treat the segment as an obstacle for later candidates so it neither crosses another accepted label nor runs through a protected marker. Near labels have no line, retaining the clean current presentation. This makes a generic tight-state fallback legible without putting a connector beside every city.

  Lifecycle: construct the overlay after map load alongside study layers, attach it once to the map container, and subscribe once to `move`, `resize`, and `remove`. `setCapitalLocationQuestion` and `revealCapitalLocationQuestion` should synchronize data after the existing GeoJSON refresh; it should mount labels only when `capitalLocationQuestion.phase === "feedback"` and `revealLabel` is true, otherwise clear synchronously. Batch `move`/`resize` placement through one `requestAnimationFrame`, project and recompute during manual pan/zoom, and do one final update on `moveend`/`idle` after camera animation or resize. Clear the overlay in the existing question resets (`setStudyPreviewMode(false)`, `updateActivity`, selected-target reset, leave-study visibility) and cancel its queued frame/listeners on map `remove`. Recompute from current projections; do not mutate authored longitude/latitude, camera state, question data, evidence, or hit layers. No reusable collision utility exists in `src/`; the compact pure placement helper behind this overlay is justified and could later serve other feedback callouts.
