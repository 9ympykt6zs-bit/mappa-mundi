## Handoff — specialist completes

### Findings

- The first exposure is already a distinct, recoverable phase: `applyMemoryTrailPromptSelection` sets a new capital to `currentPromptType: "guided"`, highlights its canonical capital target, and records only an `assisted` canonical capital-location outcome after the learner taps that target. The immediate following `name_to_place` prompt is the independent retrieval phase. The renderer currently installs the 150-choice capital-location question **only** for that retrieval phase (`src/maplibre-poc.js:12830-12835`), so Guided capital teaching presently has the ordinary capital star/highlight but no comparison-city context.
- The existing source is sufficient. `US_CAPITAL_LOCATION_CITY_CHOICES` contains one frozen record for every state with the canonical capital and exactly two display-only city records. `createCapitalLocationQuestionState` already preserves the active section capital's authored coordinate/name when its target is supplied; this is essential because section and global capital coordinates can differ. The comparison-city records carry no target, curriculum, mastery, or evidence identity.
- The feedback overlay is the appropriate label renderer. It already projects real marker coordinates, lays labels out capital first, avoids markers/controls/labels, adds leaders only when needed, recomputes after pan/zoom/resize, and is `aria-hidden`. It is restricted to `phase === "feedback"` today. The MapLibre symbol-label layer is deliberately forced hidden, so enabling it would reintroduce fixed-anchor collisions rather than solve the teaching need.
- Do not simply set the existing retrieval question to a non-answering phase during teaching. Its current state contains every state's 150 choices, replaces the normal capital source, and makes `getTargetIdsAtMapPoint` query the choice hit layer. That would show unrelated dots and could turn a comparison-city tap into a Guided miss. Teaching context must be scoped to the current state and must expose an input target only for the canonical capital.
- Resume is a required wiring point. `restoreUnitedStatesMemoryTrailMemoryTrailSnapshot` restores type, phase, highlight, and camera directly without rerunning `applyMemoryTrailPromptSelection`; it needs the same visual-context derivation as a new prompt. The saved snapshot already retains all phase/target information needed; no new persistence field is warranted.

### Recommended minimal implementation

Add a visual-only `teaching` variant to the existing capital-location question contract rather than creating city data or a second map overlay:

1. Extend `createCapitalLocationQuestionState` with a narrowly named render mode/scope (for example, `phase: "teaching"` plus `scope: "target-state"` and `interaction: "capital-only"`). In this mode, emit exactly the active state record: its active authored capital plus its two frozen distractors. Set all three `revealLabel`, set only the capital `revealCapital`, and add an explicit `isInteractive` property only to the canonical capital. Keep existing default `answering` and `feedback` construction byte-for-byte equivalent: both remain 150 choices, neutral/unlabeled before response, and preserve target-state/selected feedback disclosure.
2. Carry `isInteractive` into the GeoJSON properties and make `capital-location-choice-hit` filter it. Keep the visible dot layer for all three teaching records. In `getTargetIdsAtMapPoint`, treat a teaching context as a capital-only hit target; a comparison-dot click must return no candidate, never call `handleIncorrectMemoryTrailAnswer`, and never produce evidence. The capital keeps its current forgiving hit behavior and Guided highlight.
3. Let `CapitalLocationFeedbackLabelOverlay` accept the same revealed three records for `teaching` as for `feedback` (a neutral name such as `CapitalLocationLabelOverlay` is optional cleanup, not required for this slice). Reuse its existing capital-first placement, marker/star clearance, controls avoidance, leader behavior, movement listeners, and `aria-hidden` behavior. Preserve the feedback selected-wrong styling/priority exclusively for feedback.
4. Centralize the phase-to-renderer decision in a small `syncCapitalLocationVisualContext(memoryTrail, selection, target)` helper in `src/maplibre-poc.js`. Call it from both `applyMemoryTrailPromptSelection` and `restoreUnitedStatesMemoryTrailMemoryTrailSnapshot` after the prompt fields are set. It should install the target-state/capital-only teaching context only for a U.S. Memory Trail capital with `promptType === "guided"`; install the existing full neutral retrieval question only for `name_to_place`; otherwise clear it. This preserves standalone activity, Journey, Daily Trail, place-to-name identification, correction, and feedback behavior.
5. Keep the existing Guided camera as the default for lower-48 teaching: it fits the paired state, so its in-state city comparison records remain available without changing the search-space contract. Validate all three projected markers/names are within the actual safe map frame. If any lower-48 record fails that assertion, extend only that teaching camera calculation to fit the complete paired-state bounds plus the three display points; do not move the camera for retrieval. Section 11 needs an explicit decision: Hawaii's three Oahu records are dense and should remain on its authored Hawaii view with overlay collision handling; Alaska's Juneau/Anchorage/Fairbanks span enough longitude that the existing Alaska authored view must be measured in browser tests before claiming all three visible. If it clips one, add a teaching-only, state-context-plus-three-points fit for Alaska, then restore the authored section view before retrieval. Do not alter the special Alaska/Hawaii retrieval contract or their authored coordinates.
